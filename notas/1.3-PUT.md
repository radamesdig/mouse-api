Quando o cliente faz uma requisição usando o PUT, ele deve se atentar que todos os campos já enviados na requisição POST devem ser enviados novamente, já com os valores alterados. Isso ocorre pois o PUT substitui a pessoa inteira pela que o cliente enviou, por isso, temos que enviar tudo que queremos que fiquem como valores dos campos daquela pessoa. 

Caso algum campo seja de preenchimento não obrigatório, mas já tendo sido informado valor inicialmente no POST, atente-se para que o valor continue sendo enviado no PUT. Caso contrário, a resposta do PUT será um valor null para o campo.

Os códigos de status HTTP esperados são:

1. 200 - Caso o PUT seja executado com sucesso
2. 422 - Caso haja algum problema na validação, com algum campo faltando na requisição ou algum problema no id informado no parâmetro
3. 404 - Caso o id informado no parâmetro seja inexistente
